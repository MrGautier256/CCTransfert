Première version stable de **CCTransfert** : transférer une session Claude Code d'une machine à une autre (Linux ↔ Linux, Linux ↔ Windows) ou d'un dossier à un autre, puis la reprendre avec `claude -r` comme si de rien n'était.

## Ce que ça fait

- **Export** d'une session dans un fichier `.CCTransfert`. Il contient :
  - le transcript, les sous-agents et les résultats d'outils ;
  - les sauvegardes du **rewind** (file-history), les plans et les tâches ;
  - en option, la mémoire du projet et l'historique des prompts.
- **Import** avec réécriture de tous les chemins :
  - `cwd`, entrées et résultats d'outils, clés de file-history et texte libre ;
  - toutes les formes Windows : `C:\…`, `C:/…`, échappée et Git Bash `/c/…`.

  Les blocs *thinking* signés, les images et les identifiants restent intacts à l'octet près.
- **Nom du dossier projet calculé exactement comme Claude Code**, y compris le hash des chemins de plus de 200 caractères.
- **Gestion des conflits d'ID** (aller-retour A → B → A, ou copie avec un nouvel ID), avec sauvegarde et `CCTransfert undo`.
- **Interface graphique locale** :
  - quatre onglets : Exporter, Importer (glisser-déposer, aperçu avant/après), Historique (annulation) et Diagnostic ;
  - servie uniquement sur `127.0.0.1`, protégée par un jeton, sans aucune ressource externe.
- **Python 3.9+, aucune dépendance.**

## Installation

**Avec la wheel jointe** (Linux et Windows) :

```sh
pipx install cctransfert-1.0.0-py3-none-any.whl     # ou : uv tool install cctransfert-1.0.0-py3-none-any.whl
CCTransfert doctor
```

**Depuis les sources** (archive ou `git clone`) :
- Linux : `bin/CCTransfert`.
- Windows : `bin\CCTransfert.cmd`.
- Interface graphique, sans installation : **`CCTransfert.pyw`** à la racine (double-clic sous Windows ; sous Linux, clic droit puis « Exécuter comme un programme »).

**Icône à cliquer** : `CCTransfert gui --install-shortcut` l'ajoute au menu des applications et au bureau.

## Utilisation en deux commandes

```sh
# sur le PC source, dans le dossier du projet (après /exit dans la session)
CCTransfert export
# sur le PC cible
CCTransfert import MonProjet_….CCTransfert --to "/chemin/du/projet"
cd "/chemin/du/projet" && claude -r
```

Ou tout à la souris : `CCTransfert gui`.

## Ce qui a été testé

- **Linux, Claude Code 2.1.258 à 2.1.301.** Une vraie session exportée puis importée dans un autre dossier :
  - elle apparaît dans `claude -r` ;
  - elle se reprend en citant les chemins du nouveau dossier ;
  - le **rewind restaure les fichiers** après le transfert.
- **Aller-retour Linux → Windows (simulé) → Linux** sur 82 transcripts réels (75 723 lignes) : aucune erreur, blocs thinking intacts.
- **59 tests automatisés** :
  - transferts Linux ↔ Windows ;
  - espaces et accents dans les chemins ;
  - conflits, undo ;
  - zip-slip et sha256 ;
  - API de l'interface graphique.

## À savoir

- **Windows** n'a été validé que par simulation pour l'instant. La checklist [docs/TEST-WINDOWS.md](https://github.com/MrGautier256/CCTransfert/blob/v1.0.0/docs/TEST-WINDOWS.md) décrit la validation sur un vrai PC. Vos retours (et la sortie de `CCTransfert doctor --json`) sont les bienvenus.
- **Le code du projet n'est pas transféré** : synchronisez-le avec git. Les serveurs MCP et les settings ne sont pas transférés non plus.
- **Sessions `claude -p`** : Claude Code les exclut de son picker `claude -r`. Reprenez-les avec `claude --resume <id>`.
- **Format des transcripts** : il est interne à Claude Code et non documenté. L'outil le lit de façon défensive, mais une future version de Claude Code pourra demander une adaptation.
- **Secrets** : un transcript peut contenir des secrets en clair. Transférez le fichier par un canal de confiance, ou utilisez `--encrypt` (age ou gpg).

Détails du format de stockage de Claude Code : [docs/FORMAT.md](https://github.com/MrGautier256/CCTransfert/blob/v1.0.0/docs/FORMAT.md).
